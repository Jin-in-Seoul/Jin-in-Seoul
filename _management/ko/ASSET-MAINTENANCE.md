# 자산 관리 — Jin-in-Seoul

저장소: `Jin-in-Seoul/Jin-in-Seoul` (`main`). 공개 사이트: https://jin-in-seoul.com/.

## 1. 목적

이 문서는 Jin-in-Seoul.com에 공개되는 이미지, 음원, PDF 및 EPUB 판본의 관리 원칙을 정한다.

목표:

- 기존 저장소 구조와 안정적인 공개 URL 보존.
- 저장 공간 사용량 및 페이지 로딩 성능 관리.
- 공개 자산의 우발적인 교체 또는 삭제 방지.
- 원본 자료와 웹용 파일의 분리.
- 향후 추가 작업의 일관된 절차 유지.

**단순히 일관성을 맞추기 위해 기존 공개 자산을 재구성하거나 수정하지 않는다.** 공개 자산의 변경에는 구체적인 이유와 작가의 승인이 필요하다.

이 문서는 기술 관리 문서이다. 에세이에 어떤 사진을 몇 장, 어디에 배치할지는 작가가 결정한다. 기술 지침은 문학적·편집적 결정을 우선하지 않는다.

공개 페이지는 미디어와 분리하여 관리한다.

- `music/` — 음악 페이지; `assets/audio/music/` — MP3 음원.
- `downloads/` — 디지털판 목록; `assets/downloads/` — PDF 및 EPUB 파일.

이 분리는 의도된 것이며 보존해야 한다.

## 3. 이미지 관리

### 3.1 저장 위치

새 Gray Note 이미지는 `/assets/images/gray-note/`에 저장한다. 새로운 사진 에세이에는 다음과 같이 내용을 설명하는 하위 디렉터리를 사용한다.

```text
assets/images/gray-note/
└── venice-to-athens/
    ├── 01-venice-port.webp
    ├── 02-ferry-deck.webp
    └── 03-mediterranean-sea.webp
```

이 파일명은 예시이며 의무적인 이름이 아니다. 기존 이미지 경로는 변경하지 않는다.

### 3.2 이미지 최적화

새 사진은 업로드 전에 최적화한다. 기본 권장 기준:

| 항목 | 권장 기준 |
| --- | --- |
| 우선 형식 | WebP |
| 대체 형식 | JPEG |
| 긴 변의 최대 길이 | 1600픽셀 |
| 일반적인 파일 용량 목표 | 150–300KB |
| 세부 묘사가 많은 사진 | 필요시 약 500KB |
| 색상 프로파일 | sRGB |
| 메타데이터 | 웹용 사본의 불필요한 위치 및 기기 정보 제거 |

이는 지침이지 절대적인 제한이 아니다. 특히 글자, 건축물, 세부 묘사의 시각적 품질을 검토해야 한다. 이미 권장 크기보다 작은 이미지는 확대하지 않는다.

### 3.3 역사적 진정성과 원본 사진

과거의 여행 사진은 촬영 당시의 시간과 장소를 기록한 것이다. 원래 모습을 보존한다. 웹 발행을 위한 준비는 일반적으로 크기 조정, 압축, 형식 변환과 필요한 기술적 보정으로 한정한다.

시각적 매력만으로 색상, 구도 또는 사진 속 내용의 변경을 정당화하지 않는다. 일반적인 최적화에는 과거 사진 속 요소의 제거, 교체 또는 생성이 포함되지 않는다. 실질적인 시각적 편집에는 작가의 명시적 결정이 필요하다.

원본 파일은 GitHub 외부의 개인 저장 공간에 보존하고 최적화된 웹용 사본 및 독립적인 백업을 별도로 유지한다. 변환 과정에서 원본을 덮어쓰지 않는다.

기존 `/assets/images/originals/` 디렉터리에는 이전부터 보관한 원본이 있을 수 있다. 변경에는 개별 파일 검토가 필요하다. 저장 방식의 통일만으로 삭제나 이동을 정당화하지 않는다.

### 3.4 사진 에세이

사진은 작가의 서술에 기여해야 한다. 에세이별 이미지 수는 정해져 있지 않다.

의미 있는 파일명과 내용을 설명하는 `alt` 속성을 사용한다. 적절한 경우 이미지 크기를 지정하고 첫 화면 아래에 있는 이미지에는 지연 로딩을 적용한다.

**사진 선택, 수량, 순서 및 배치는 작가가 결정한다.** 사진, 문단 또는 설명문의 재배열에는 승인이 필요하다.

## 4. 음원 관리

### 4.1 저장 위치

공개 음원은 `/assets/audio/music/`, 음악 페이지는 `/music/`에 유지한다. 일관성을 맞춘다는 이유만으로 공개 파일을 이동하지 않는다.

### 4.2 음원 형식과 이름

현재 발행 형식은 MP3이며 변경 승인이 없는 한 기본 형식으로 유지한다. 동일한 음원의 중복 사본을 피한다. 기존 파일명 규약 및 `-ja`와 같은 언어 접미사를 보존한다.

새 파일은 내용을 설명하는 소문자 영문과 하이픈을 사용한다.

### 4.3 음원 갱신

음원을 추가하거나 교체하기 전에:

1. 작품, 버전 및 언어 확인.
2. 재생, 길이, 시작과 끝, 명백한 음질 결함 검증.
3. 음악 페이지의 올바른 음원 링크 확인.
4. 음악 목록 및 관련 내비게이션 검증.
5. 승인된 교체로 기존 공개 음원이 변경되는 경우 브라우저 캐시 및 직접 링크 검토.

승인 없이 기존 음원 파일을 교체하거나 이름을 변경하지 않는다.

## 5. PDF 및 EPUB 관리

### 5.1 저장 위치

디지털판은 `/assets/downloads/` 아래에 작품과 언어별로 저장하며 필요한 경우 부별 디렉터리를 사용한다.

```text
assets/downloads/
└── a-dictionary-of-galactic-extinction/
    └── part-01/
        ├── en/
        ├── ja/
        └── ko/
```

다운로드 목록은 별도로 `/downloads/`에 유지한다.

### 5.2 발행 중단

**2026년 11월 2일자 발행 공지는 여전히 유효하다.**

신뢰할 수 있는 제작 및 검증 절차를 확립할 때까지 다운로드용 PDF 및 EPUB 판본의 업로드와 갱신을 중단한다. 중단 기간에 해당 판본의 기존 오류를 수정하지 않는다.

최신 문학 본문은 사이트의 HTML 페이지에서 제공한다.

### 5.3 발행을 재개할 경우

새롭게 승인된 발행에는 다음 검증이 필요하다.

- 본문 전체, 정확한 장 순서 및 문단 형식.
- 언어별 글꼴, 조판 및 렌더링.
- 목차 및 내부 내비게이션.
- 대표적인 뷰어에서 파일 열기.
- 파일명, 버전 및 다운로드 링크의 정확성.

기존 버전이 지정된 다운로드 파일을 알리지 않고 덮어쓰지 않는다.

## 6. 파일명

새로 공개하는 미디어에 권장하는 이름 규약:

- 소문자 라틴 문자와 숫자.
- 단어 사이의 하이픈.
- 작품 또는 장면을 식별하는 설명적 이름.
- 필요한 경우 언어 접미사.
- 기존 규약에서 요구할 경우 다운로드 판본의 날짜 및 버전 번호.

예시:

- `01-venice-port.webp`
- `autumn-rain-blue-night-ja.mp3`
- `sweater-en-20260930-ver-001.pdf`

파일명 규약만으로 공개 파일의 이름 변경을 정당화하지 않는다.

**기존 URL 보존을 이름의 통일성보다 우선한다.**

## 7. 저장 공간 및 성능

저장소에 저장한 자산은 저장소 크기에 영향을 주며 공개된 경우 GitHub Pages 사이트 크기 및 대역폭에도 영향을 줄 수 있다. 저장소 크기와 공개 사이트 크기는 서로 다른 측정값이다.

사진 에세이 또는 상당한 규모의 새로운 미디어를 발행하기 전에:

1. 모든 신규 파일의 총용량 추정.
2. 개별 이미지 최적화 확인.
3. 개별 사진의 용량에 더하여 **에세이에 사용된 모든 이미지의 합계 용량 계산**.
4. 최초 로딩 이미지와 이후 로딩 이미지를 포함하여 모바일 연결에서 예상되는 페이지 로딩 영향 검토.
5. 관련 저장소 및 GitHub Pages 저장 용량 제약 검토.
6. 중복 사본 방지 및 필요한 경우 단계별 업로드.

**자동 이미지 수 제한이나 모든 에세이에 적용되는 용량 상한은 없다.** 총용량은 검토 지표이며 최종 구성은 작가가 결정한다. 페이지가 이례적으로 무거울 경우 압축이나 로딩 방식을 먼저 개선한다.

음원과 다운로드 판본은 최적화된 사진보다 더 많은 저장 공간을 사용할 수 있다. 저장 용량의 증가를 정기적으로 검토한다.

외부 호스팅은 기본 정책이 아니다. 실제 저장 공간, 대역폭 또는 운영상 필요가 추가 복잡성을 정당화할 때 도입한다.

## 9. 보존 및 변경 관리

기존 공개 사이트를 기준 상태로 삼는다.

다음 작업은 제외한다.

- 승인 없이 기존 자산 디렉터리를 이동하거나 공개 파일의 이름을 변경하는 작업.
- 원본을 압축된 파생 파일로 교체하는 작업.
- 공개 미디어의 자동 재압축, 디자인 변경 또는 기타 편집.
- 모든 참조를 확인하지 않은 채 미사용으로 보이는 파일을 삭제하는 작업.
- 자산 관리 중 문학 본문이나 문단 경계를 변경하는 작업.
- 작가의 결정 없이 사진 선택이나 레이아웃을 변경하는 작업.
- 승인 없이 PDF/EPUB 발행을 재개하는 작업.

승인된 변경 전에는 영향받는 파일 참조, 공개 URL, 캐시 및 색인에 미치는 결과를 파악하고 GitHub의 최신 `main`과 파일 SHA를 확인한다. 이후 검증에는 변경된 모든 파일의 재조회 및 가능한 경우 Pages 배포의 별도 확인이 포함된다.
