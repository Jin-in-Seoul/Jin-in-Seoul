# ABC — Jin-in-Seoul 사이트 운영 및 관리 규정

## 1. 목적

본 규정은 Jin-in-Seoul의 문학적 정체성을 유지하고 작품의 안정적인 발행과 보존, 사이트 운영의 일관성 및 기술적 안정성을 확보하는 것을 목적으로 한다.

## 2. 사이트의 정체성

Jin-in-Seoul은 소설, 단편소설, 동화, 에세이, 하이쿠, 음악 및 한국의 옛소설을 소개하는 개인 문학 사이트이다.

- 영어권 독자를 우선으로 하며, 일반적인 다국어 표기에는 English · 日本語 · Français · 한국어 순서를 적용한다. 하이쿠와 음악 등 개별 작품군의 기존 표기 방식은 해당 세부 규정과 편집 원칙에 따른다.

- Jin-in-Seoul은 작품의 창작 및 발행에 사용되는 필명이다. 공개 저자 정보는 승인된 필명을 기준으로 한다.

## 3. 운영 환경

- 공식 사이트: https://jin-in-seoul.com/
- 저장소: Jin-in-Seoul/Jin-in-Seoul
- 운영 브랜치: main
- 발행 환경: GitHub Pages / Jekyll

- 기존 작품의 URL과 발행 구조는 지속적으로 유지하는 것을 원칙으로 한다.

## 5. 작품의 보존과 편집

- 작품의 본문, 제목, 번역, 문단 구성 및 고유한 조판은 창작과 편집의 결과물로서 존중되고 보존되어야 한다.

- 문학적·편집적 변경은 작가의 결정에 따른다. 기술적 유지보수와 문학적 편집은 구분한다. 관리 효율화를 목적으로 기존 작품의 내용이나 발행 형식을 변경하지 않는다.

- 외국어 번역은 승인된 한국어 원문을 기준으로 하며, 한국의 옛소설은 확정된 현대 한국어판과 해당 원전 및 번역 규정에 따른다.

## 6. 디자인 및 독자 환경

- 사이트는 간결하고 일관된 문학적 조판을 지향한다.

- 메뉴, 링크, 버튼 및 기타 시각적 요소는 명확한 기능과 필요성을 가진 경우에 한하여 적용한다.

- 다국어 발행의 목적은 각 언어권의 독자에게 해당 언어로 작품을 제공하는 데 있다. 언어 선택은 작품 목록을 중심으로 이루어지며, 본문 내 언어 전환 기능의 추가에는 별도의 승인이 필요하다.

- 개별 작품의 특성에 따라 확립된 조판과 디자인을 유지한다. 특히 Sweater의 일기체 조판과 관련 CSS는 CSS 관리 규정에 따라 보호한다.

## 7. 기술적 유지보수

기술적 유지보수는 기존 발행 체계의 안정성, 작업의 정확성 및 관리 효율성 향상을 목적으로 한다.

- 새로운 관리 기능은 가능한 한 기존 HTML, CSS 및 발행 구조와 독립적으로 구성한다. 작업 범위는 사전에 확정하며, 승인된 범위를 벗어난 변경은 별도의 검토와 승인을 거친다. 검토 및 의견 요청은 변경 승인과 구분한다.

## 8. 관리 도구

관리용 도구는 _maintenance/ 디렉터리에 별도로 보관한다.

| 도구 | 기능 |
| --- | --- |
| [plan_release.py](../../_maintenance/plan_release.py) | 작품군별 신규 발행 계획 및 변경안 생성 |
| [plan_gray_note_release.py](../../_maintenance/plan_gray_note_release.py) | 신규 Gray Note 발행 계획 생성 |
| [check_change_scope.py](../../_maintenance/check_change_scope.py) | 변경 범위 검증 |
| [report_site_status.py](../../_maintenance/report_site_status.py) | 배포 및 기술 검사 현황 확인 |

- 발행 계획 도구는 검토용 변경안을 출력하며 기존 파일을 직접 수정하거나 발행하지 않는다. 공통 도구는 은하 멸망 사전 연작, 허수아비 거리, Sweater, 단편소설, 동화, 한국의 옛소설, Gray Note, Haiku 및 Music의 신규 등록 계획을 지원하도록 작성되었다. 기존 작품의 번역판 추가, 자산 업로드 및 특수 발행 형식은 별도의 검토가 필요하다.

- 2026년 11월 27일 GitHub Actions에서 관리 도구 4개의 읽기 전용 실행 검증을 완료했다([검증 실행 46001390330](https://github.com/Jin-in-Seoul/Jin-in-Seoul/actions/runs/46001390330)). 공통 발행 계획 도구는 한국의 옛소설을 포함한 작품군 9개의 모의 시험을 통과했다. Gray Note 발행 계획 도구는 독립 시험 자료로 변경안을 생성하고 기존 작품의 중복 등록을 차단했다. 변경 범위 검사 도구는 허용·거부 사례를 포함한 자체 시험을 통과했다. 사이트 상태 보고 도구는 실제 GitHub Actions 데이터를 조회하고 보고서를 생성했다. 이 결과는 도구의 기본 작동 검증이며 실제 작품 발행이나 배포의 검증을 의미하지 않는다. 도구는 모두 읽기 전용이고 실제 변경에는 별도의 검토와 승인이 필요하다.

- 관리 도구와 공개 사이트는 기능적으로 분리한다. 관리 도구의 도입이나 변경이 기존 작품과 독자 환경에 영향을 주어서는 안 된다.

## 9. 작품의 발행

신규 작품과 번역판의 발행에는 해당되는 다음 항목에 대한 확인이 수반된다.

- 작품 본문 및 제목
- 작품 목록과 해당되는 메인 페이지 항목
- 사이트맵과 내부 검색 색인
- Canonical 및 Hreflang
- 검색 및 공유용 메타데이터
- JSON-LD 구조화 데이터
- Publication Log

- 발행 기록과 검색 정보는 실제로 공개된 작품 및 언어판을 기준으로 작성한다. 발행 일자와 언어 순서, 기존 기록의 보존은 Publication Log 규정에 따른다.

- PDF 및 EPUB 발행 중단 등 디지털 자산 관련 결정은 자산 관리 규정에 따른다.

## 10. 변경 관리 및 검증

- 모든 변경은 최신 운영 브랜치를 기준으로 이루어진다. 변경 전 기준 커밋과 대상 파일의 최신 상태를 확인하고, 변경 후 파일을 재조회한다.

- 변경 전후의 전체 파일 상태를 비교하여 승인된 작업 범위의 준수 여부를 확인한다. GitHub 소스 반영, 자동 검사, GitHub Pages 배포 및 공개 사이트의 상태는 각각 독립적인 검증 항목으로 취급한다.

- 검사 성공 여부와 실제 오류 건수는 구분한다. 확인되지 않은 사항은 검증 완료로 기록하지 않는다.

## 11. 복구 및 이력 보존

- 기술적 오류가 발생한 경우 변경 범위와 원인을 확인하고 필요한 범위에서 이전의 정상 상태를 복구한다.

- 복구 과정에서는 관련 없는 작업과 기존 발행 기록을 보존한다. 변경 및 복구 이력은 Git의 커밋 기록을 통해 추적할 수 있도록 유지하며, 복구 결과는 기준 상태와 비교하여 검증한다.

## 12. 규정의 유지 및 개정

- 본 규정과 분야별 관리 규정은 사이트의 운영 환경 및 발행 체계에 따라 개정할 수 있다.

- 규정의 개정은 작가의 승인을 거치며, 기존 규정과의 일관성을 유지한다.
